# web-dashboard

داشبورد Nuxt 4 روی API Gateway. همان چیزی که تا حالا فقط با `curl` قابل استفاده
بود: ورود، پروژه‌ها، شروع تحلیل، و خواندن گزارش.

```bash
npm install --legacy-peer-deps
npm test                                   # ۱۴ تست، بدون مرورگر
npm run dev                                # http://localhost:3000

# ساخت و اجرای نسخه‌ی نهایی
npm run build
NUXT_PUBLIC_API_BASE=http://127.0.0.1:8000/api node .output/server/index.mjs
```

`NUXT_PUBLIC_API_BASE` آدرس گیت‌وی است و در زمان **اجرا** خوانده می‌شود، نه
زمان build — همان باندل ساخته‌شده در توسعه و production کار می‌کند.

## صفحه‌ها

| مسیر | کارش |
| --- | --- |
| `/login`، `/register` | گرفتن توکن از گیت‌وی |
| `/workflows` | فهرست تحلیل‌ها؛ تا وقتی چیزی در حال اجراست خودش تازه می‌شود |
| `/workflows/new` | شروع یک ممیزی سه‌مرحله‌ای |
| `/workflows/[id]` | گزارش: خلاصه، اعداد اصلی، مراحل، فرصت‌ها، رقبا |
| `/projects` | سایت‌هایی که دنبال می‌کنید |

## تصمیم‌ها

**بدون SSR.** گیت‌وی با توکن Bearer احراز هویت می‌کند، نه کوکی. رندر سمت سرور
یعنی آن سرور باید توکن هر بازدیدکننده را نگه دارد تا به‌جای او درخواست بزند —
یک جای دوم برای زندگی توکن‌ها که این پروژه دلیلی برای داشتنش ندارد.

**توکن در `sessionStorage`.** چون توکن Bearer است، بدون گذاشتن یک سرور واسط
گزینه‌ی HttpOnly وجود ندارد؛ بین دو انبار مرورگر، آن که با بسته شدن تب می‌میرد
پنجره‌ی کوچک‌تری است. با refresh از بین نمی‌رود، که همان چیزی است که یک داشبورد
لازم دارد.

**میدل‌ور مسیر یک راحتی است، نه یک کنترل.** داده‌ی هر صفحه از گیت‌وی می‌آید و
گیت‌وی خودش توکن را بررسی می‌کند. نگهبان مسیر داخل باندلی که در دست کاربر است
از هیچ‌چیز محافظت نمی‌کند.

**قضاوت‌ها در `app/utils/format.ts` است، نه در قالب‌ها.** «جایگاه خالی یعنی چه»،
«کِی باید polling را قطع کرد»، «هر کد وضعیت گیت‌وی چه معنایی برای کاربر دارد» —
همه توابع خالص‌اند و بدون مرورگر تست می‌شوند.

**هدر `Accept: application/json` روی هر درخواست.** بدون آن لاراول درخواست بدون
توکن را یک ناوبری مرورگر حساب می‌کند و به صفحه‌ی login که وجود ندارد ریدایرکت
می‌کند.

## چه چیزی تست شده

`npm test` منطق خالص را پوشش می‌دهد. خود اپ با یک مرورگر واقعی (Chromium با
Playwright) روی کل پشته اجرا شد: ثبت‌نام → شروع تحلیل روی یک سایت آزمایشی محلی
→ خزش و تحقیق کلمات کلیدی و بررسی جایگاه روی RabbitMQ و Postgres واقعی → رندر
شدن گزارش. اسکریپت راننده در مخزن نیست چون به سرویس‌های در حال اجرا وابسته است؛
نتیجه‌اش در `ARCHITECTURE.md` نوشته شده.

## هشدارهای `npm audit`

چند مورد high در ابزار build (زنجیره‌ی `glob`/`brace-expansion` زیر nitropack و
archiver) گزارش می‌شود. اینها در باندلی که به مرورگر می‌رود نیستند و رفعشان
نیازمند نسخه‌ی بالادستی جدیدتر است. `--legacy-peer-deps` هم به‌خاطر باگ حل
وابستگی در npm 10.9 روی درخت Nuxt لازم است، نه به‌خاطر ناسازگاری واقعی.
