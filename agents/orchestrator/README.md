# orchestrator

گردش‌کار چندمرحله‌ای: برنامه‌ریزی، اعزام مرحله، انتظار رویداد، مرحله‌ی بعد.

```bash
python -m agents.orchestrator.worker            # ورکر باس
python -m agents.orchestrator.scheduler         # تیک زمان‌بندی
uvicorn agents.orchestrator.api:app --port 8200 # API
```

| فایل | کارش |
| --- | --- |
| `planner.py` | از هدف، مرحله‌ها را می‌سازد (تابع خالص) |
| `engine.py` | ماشین حالت؛ زیر قفل ردیف گردش‌کار تصمیم می‌گیرد |
| `store.py` | وضعیت در Postgres + استیج رویداد در outbox |
| `summary.py` | خلاصه‌ی اجرایی گزارش — لایه‌ی قانون‌محور و لایه‌ی مدل |
| `schedules.py` | «هر دوشنبه ساعت ۹» یعنی چه، و شلیک آنچه سررسیده |
| `scheduler.py` | یک حلقه‌ی ساده: سررسیده‌ها را شلیک کن، بخواب |
| `worker.py` | مصرف‌کننده‌ی رویدادها |
| `api.py` | ساخت و خواندن گردش‌کار |

خلاصه‌ی گزارش دو لایه دارد: لایه‌ی قانون‌محور همیشه نوشته می‌شود (تابع خالص،
داخل همان تراکنش پایانی)، و لایه‌ی مدل بعد از آن و بیرون از قفل جایش را
می‌گیرد — فقط اگر `ANTHROPIC_API_KEY` ست باشد و مدل جواب بدهد. بدون کلید، هیچ
چیزی از کار نمی‌افتد.

زمان‌بندی سه تصمیم دارد که راحت غلط از آب درمی‌آیند: **ساعت ۹ در کدام
منطقه‌ی زمانی** (ذخیره و محاسبه در همان منطقه، وگرنه با تغییر ساعت یک ساعت
جابه‌جا می‌شود)، **۳۱ در ماه ۳۰روزه** (به آخر ماه چسبانده می‌شود، نه رد شدن از
آن ماه)، و **ماشینی که یک هفته خاموش بوده** (یک اجرا، نه هفت تا). هر سه تابع
خالص‌اند و بدون ساعت تست می‌شوند.

شلیک و جابه‌جا کردن `next_run_at` در **یک تراکنش** انجام می‌شود و ردیف با
`FOR UPDATE SKIP LOCKED` گرفته می‌شود — همان الگوی رله. برای همین می‌شود دو
scheduler را همزمان اجرا کرد.

جزئیات تصمیم‌ها در `ARCHITECTURE.md`.
