# reporting

اولین خروجی‌ای که کاربر می‌تواند برای کس دیگری بفرستد.

```bash
uvicorn services.reporting.api:app --port 8008
python -m services.reporting.worker

# سند نهایی
curl "localhost:8008/v1/reports/<id>/document" -o report.html
curl "localhost:8008/v1/reports/<id>/document?format=md" -o report.md
```

| فایل | کارش |
| --- | --- |
| `render.py` | تابع خالص: گردش‌کار → Markdown و HTML خودبسنده |
| `source.py` | خواندن گردش‌کار از ارکستریتور |
| `store.py` | یک `JobTable` روی `reports` |
| `api.py` | ساخت گزارش + `GET /document` که خود فایل را می‌دهد |
| `worker.py` | مصرف `report.requested` و `workflow.completed` |

## تصمیم‌ها

**سند خودبسنده است.** هیچ درخواستی به بیرون ندارد — نه فونت از CDN، نه
استایل‌شیت، نه اسکریپت. گزارشی که استایلش را از اینترنت می‌گیرد، گزارشی است که
شش ماه بعد، آفلاین، برای کسی که ایمیلش کرده‌اند خراب باز می‌شود؛ و دقیقاً
همین‌طور خوانده می‌شود.

**PDF یعنی چاپ همین HTML.** موتور PDF سمت سرور اضافه نشد. به‌جایش قواعد چاپ
(`@page A4`، `break-inside`) داخل خود فایل است، پس «چاپ → ذخیره به‌صورت PDF»
در مرورگر خروجی درستی می‌دهد. این یک انتخاب است، نه کمبود: یک وابستگی سنگین
کمتر، و فایلی که همه‌جا باز می‌شود.

**هر متن از فیلتر escape رد می‌شود.** عنوان صفحه از سایت *یک نفر دیگر* می‌آید.
گزارشی که آن را خام رندر کند، راهی است برای اینکه یک صفحه‌ی خزیده‌شده به
مرورگر کسی که گزارش را باز می‌کند حمله کند.

**HTML از روی همان داده ساخته می‌شود، نه از روی Markdown.** تبدیل Markdown به
HTML یعنی گذاشتن یک پارسر بین گزارش و خواننده‌اش بدون هیچ سودی، و هر باگ
escape در آن پارسر زندگی می‌کند.

**گردش‌کار موقع رندر تازه خوانده می‌شود.** payload رویداد `workflow.completed`
خلاصه‌ی مرحله‌هاست؛ سند کل گزارش را می‌خواهد. ضمناً یک مسابقه را باریک می‌کند:
خلاصه‌ی نوشته‌ی مدل چند لحظه **بعد از** تمام شدن گردش‌کار و بیرون از قفل نوشته
می‌شود. باریک، نه بسته — سندی که همان لحظه ساخته شود ممکن است خلاصه‌ی
قانون‌محور را بگیرد، و `summary_source` همین را می‌گوید.

**هر گردش‌کار یک سند خودکار می‌گیرد.** بدون این بررسی، هر تحویل مجدد رویداد یک
نسخه‌ی تازه می‌ساخت. درخواست صریح (`report.requested`) همیشه رندر می‌کند — همان
راهی که کسی خلاصه‌ی مدل را که دیرتر رسیده برمی‌دارد.

**دومین مصرف‌کننده‌ی `workflow.completed`.** ورکر ارکستریتور همان رویداد را
برای نوشتن خلاصه می‌گیرد. هیچ‌کدام از دیگری خبر ندارد؛ همین fan-out دلیل وجود
باس است.
