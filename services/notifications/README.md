# notifications

آخرین حلقه: وقتی گزارش آماده شد، به کسی بگو.

```bash
uvicorn services.notifications.api:app --port 8009
python -m services.notifications.worker
```

| فایل | کارش |
| --- | --- |
| `deliver.py` | تابع خالص: چه چیزی، برای چه کسی، و آیا شکست ارزش تلاش دوباره دارد |
| `channels.py` | دو ترابری: وبهوک و ایمیل — تنها جایی که به شبکه دست می‌زند |
| `store.py` | کانال‌ها و تحویل‌ها؛ فقط Postgres |
| `api.py` | مدیریت اشتراک‌ها + `POST /v1/channels/{id}/test` |
| `worker.py` | مصرف `report.rendered` و `workflow.completed` |

## تصمیم‌ها

**یک‌بار فرستادن با ایندکس یکتا، نه با حافظه.** تحویل at-least-once است، پس
همان رویداد می‌تواند دوبار برسد. جفت `(channel_id, event_id)` یک قید یکتا در
دیتابیس دارد: ورکر اول INSERT می‌کند، دومی conflict می‌گیرد و می‌ایستد. هر
چیز دیگری (یک `set` در حافظه، یک قفل) با اولین ری‌استارت یعنی دو ایمیل درباره‌ی
یک گزارش. `event_id` هم همانی است که تولیدکننده در outbox گذاشته، پس از
ری‌استارت رله هم جان سالم به در می‌برد.

**payload لینک است، نه گزارش.** بدنه‌ی وبهوک در لاگ *یک نفر دیگر* می‌نشیند و
گزارش چیزی نیست که آنجا جا بگذاری.

**آدرس وبهوک از SSRF guard رد می‌شود — هم موقع ساخت، هم موقع ارسال.** خطرناک‌ترین
آدرس کل پلتفرم همین است: کاربر تایپش می‌کند و سروری که داخل شبکه‌ی خصوصی نشسته
درخواستش را می‌زند. بدون این، یک تنانت می‌توانست اعلانش را به
`169.254.169.254` وصل کند و اعتبارنامه‌های سرور را بخواند. آدرسی که resolve
نشود هم رد می‌شود: guard نمی‌تواند ثابت کند نام ناشناخته داخلی نیست.

**امضا روی همان بایت‌هایی است که فرستاده می‌شود.** بدنه یک‌بار سریال می‌شود و
HMAC روی همان بایت‌ها محاسبه می‌شود؛ امضا روی سریال‌سازی دوباره‌ی دیکشنری چیزی
است که گیرنده نمی‌تواند بازتولیدش کند.

**راز فقط یک‌بار نشان داده می‌شود** — لحظه‌ی ساخت کانال. فهرست کانال‌ها
رازها را برنمی‌گرداند، چون فهرست همان چیزی است که سر از اسکرین‌شات و لاگ
درمی‌آورد. آدرس ایمیل در فهرست تحویل‌ها هم ماسک می‌شود.

**۵۰۳ دوباره تلاش می‌شود، ۴۰۴ نه.** شکست موقت claim را پس می‌دهد تا تحویل بعدی
برش دارد؛ شکست دائمی ردیفش را نگه می‌دارد — همان ردیف جواب «چرا به کسی خبر
نرسید» است.

**هیچ کانالی یعنی هیچ کاری.** رویداد بی‌صدا رد می‌شود؛ سرویسی که برای هر
گردش‌کار بدون مشترک خطا بدهد، لاگ را پر می‌کند بدون اینکه چیزی درست شود.
