# ایجنت سئو

یک ابزار شخصی سئو که روی کامپیوتر خودت اجرا می‌شود و سه کار می‌کند:

1. **بررسی سئوی سایت** — سایت را می‌خزد و بیش از ۴۰ قانون سئو را رویش اجرا می‌کند
2. **تحقیق کلمات کلیدی** — بروزترین عبارت‌هایی که مردم همین حالا در هر حوزه‌ای جستجو می‌کنند
3. **پیشنهاد بهبود** — فهرست اولویت‌بندی‌شده‌ی کارهایی که باید انجام بدهی

قوانین بر اساس راهنماهای فعلی گوگل نوشته شده‌اند: ایندکس موبایل‌محور (جولای ۲۰۲۴)،
سیستم محتوای مفید، معیارهای E-E-A-T، Core Web Vitals با INP (جایگزین FID از مارس ۲۰۲۴)،
سیاست‌های اسپم، و بهینه‌سازی برای AI Overviews و موتورهای جستجوی مبتنی بر هوش مصنوعی.

گزارش‌ها دوزبانه‌اند: عنوان ایرادها به انگلیسی (اصطلاح استاندارد سئو) و توضیح و راه‌حل به فارسی.

---

## راه‌اندازی

```bash
git clone <آدرس-این-مخزن> seo
cd seo
./run.sh
```

`run.sh` خودش محیط مجازی می‌سازد، وابستگی‌ها را نصب می‌کند و داشبورد را روی
<http://127.0.0.1:5000> بالا می‌آورد و مرورگر را باز می‌کند.

اگر ترجیح می‌دهی دستی انجام بدهی:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m seoagent
```

نیازمندی: پایتون ۳.۱۰ یا بالاتر.

## نصب روی سرور مجازی

روی یک سرور تازه‌ی اوبونتو/دبیان، با یک دستور:

```bash
curl -fsSL https://raw.githubusercontent.com/ferya3/seo/claude/personal-seo-agent-3n2suc/deploy/install.sh | sudo bash
```

اگر دامنه داری و می‌خواهی با HTTPS بالا بیاید:

```bash
curl -fsSL https://raw.githubusercontent.com/ferya3/seo/claude/personal-seo-agent-3n2suc/deploy/install.sh | sudo DOMAIN=seo.example.com bash
```

اسکریپت این کارها را می‌کند:

- کاربر سیستمی `seoagent` بدون شل می‌سازد (سرویس با root اجرا نمی‌شود)
- پروژه را در `/opt/seoagent` نصب و محیط مجازی می‌سازد
- **یک رمز تصادفی تولید می‌کند** و در انتها نمایش می‌دهد
- سرویس systemd را با **gunicorn** راه می‌اندازد، بایند روی `127.0.0.1`
- اگر `DOMAIN` داده باشی: nginx را تنظیم و گواهی Let's Encrypt را می‌گیرد
- سلامت سرویس را قبل از اعلام موفقیت بررسی می‌کند

### چرا اینطوری اصولی است

| مورد | تصمیم |
| --- | --- |
| سرور اپلیکیشن | gunicorn، نه سرور توسعه‌ی Flask |
| تعداد ورکر | **یک ورکر با ۸ ترد** — عمداً. کارها در ترد پس‌زمینه اجرا می‌شوند و وضعیتشان داخل همین پروسه است؛ ورکر دوم به درخواست وضعیتِ کاری که ندیده جواب «پیدا نشد» می‌داد. کار هم شبکه‌محور است نه CPU‌محور، پس ترد جواب می‌دهد |
| تایم‌اوت | `--timeout 0` چون یک خزش واقعاً می‌تواند از ۳۰ ثانیه‌ی پیش‌فرض بیشتر طول بکشد |
| احرازهویت | HTTP Basic **داخل خود اپ**، نه فقط در nginx. اگر روزی پیکربندی nginx خراب شود، سرویس همچنان قفل است |
| بایند | `127.0.0.1` و nginx جلویش. اپ اگر بخواهی روی آدرس عمومی بدون رمز بالا بیاید، **بالا نمی‌آید** و دلیلش را می‌گوید |
| ایزولاسیون | سرویس با کاربر اختصاصی، `ProtectSystem=strict`، `PrivateTmp`، فیلتر syscall، سقف حافظه ۱ گیگ |
| نگهداری گزارش‌ها | روی دیسک در `/var/lib/seoagent` — با ری‌استارت و ریبوت از بین نمی‌روند |
| SSRF | کرالر آدرس‌های شبکه‌ی داخلی و metadata ابری را رد می‌کند (پایین‌تر) |

### مدیریت سرویس

```bash
systemctl status seoagent          # وضعیت
systemctl restart seoagent         # ری‌استارت (بعد از تغییر تنظیمات)
journalctl -u seoagent -f          # لاگ زنده
```

تنظیمات در `/etc/seoagent.env` است — رمز، کلید API و بقیه‌ی متغیرها. بعد از تغییر
`systemctl restart seoagent` بزن.

### به‌روزرسانی

```bash
sudo bash /opt/seoagent/deploy/install.sh
```

همان اسکریپت، دوباره. کد را به‌روز می‌کند، وابستگی‌ها را نصب می‌کند و سرویس را
ری‌استارت می‌کند. فایل `/etc/seoagent.env` و گزارش‌های ذخیره‌شده دست نمی‌خورند.

### اگر دامنه نداری

سرویس روی `127.0.0.1` می‌ماند و از بیرون در دسترس نیست. از تونل SSH استفاده کن:

```bash
ssh -N -L 5000:127.0.0.1:5000 user@your-server
```

بعد در مرورگر خودت `http://127.0.0.1:5000` را باز کن. هیچ پورتی روی اینترنت باز نمی‌شود.

## امنیت

سه چیزی که برای اجرا روی سرور عمومی لازم بود و پیاده شده است:

### ۱. احرازهویت

با `SEO_AGENT_PASSWORD` فعال می‌شود (اسکریپت نصب خودش یکی تولید می‌کند). تا وقتی
تنظیم نشده باشد، اپ **حاضر نمی‌شود روی آدرس غیر لوکال بالا بیاید**:

```
خطا: داشبورد بدون رمز روی آدرس عمومی بالا نمی‌آید.
```

مسیر `/healthz` عمداً باز است تا systemd و nginx بتوانند سلامت را چک کنند.

### ۲. جلوگیری از SSRF

یک کرالر بی‌محافظ روی VPS عملاً یک پروکسی SSRF است: هر کسی که به داشبورد برسد
می‌تواند سرور را وادار کند `http://169.254.169.254/` (metadata ابری — یعنی کلیدهای
IAM) را بخواند یا شبکه‌ی داخلی را اسکن کند.

پس به‌صورت پیش‌فرض این‌ها رد می‌شوند: لوکال‌هاست، رنج‌های خصوصی (`10.`، `192.168.`،
`172.16-31.`)، link-local، و آدرس‌های metadata همه‌ی ابرهای اصلی. بررسی روی **هر
درخواست** انجام می‌شود نه فقط آدرس اولیه، چون خزش لینک‌ها و ریدایرکت‌ها را دنبال
می‌کند و یک صفحه‌ی خارجی می‌تواند مسیر را عوض کند. نام دامنه‌ای که به آی‌پی داخلی
resolve شود هم گرفته می‌شود.

اگر واقعاً می‌خواهی یک سایت روی شبکه‌ی داخلی را بررسی کنی:

```bash
SEO_AGENT_ALLOW_PRIVATE=1
```

**ولی آدرس‌های metadata حتی با این متغیر هم بلاک می‌مانند** — دلیلی وجود ندارد که یک
کرالر سئو به کلیدهای IAM سرور نیاز داشته باشد.

### ۳. محدودسازی سرویس

یونیت systemd با `ProtectSystem=strict`، `PrivateTmp`، `NoNewPrivileges`، فیلتر
syscall و سقف حافظه اجرا می‌شود. تنها مسیر قابل نوشتن `/var/lib/seoagent` است.

## داشبورد

دو تب دارد.

### تب «بررسی سئوی سایت»

آدرس سایت را می‌دهی و بقیه‌اش خودکار است. گزینه‌ها:

| گزینه | توضیح |
| --- | --- |
| کلمات کلیدی هدف | اگر پر کنی، بررسی می‌شود این عبارت‌ها در عنوان، H1 و متن کجا آمده‌اند و آیا چند صفحه سر یک کلمه با هم رقابت می‌کنند (هم‌نوع‌خواری) |
| حداکثر صفحات / عمق | سقف خزش. برای شروع ۳۰ صفحه و عمق ۳ کافی است |
| ربات | پیش‌فرض موبایل است، چون گوگل از جولای ۲۰۲۴ فقط با Googlebot موبایل ایندکس می‌کند |
| رعایت robots.txt | مسیرهای Disallow شده خزیده نمی‌شوند |
| بررسی لینک‌های خارجی | نمونه‌ای از لینک‌های خروجی را تست می‌کند تا لینک‌های مرده پیدا شوند |
| Core Web Vitals واقعی | داده‌ی واقعی کاربران را از PageSpeed Insights می‌گیرد (کندتر، نیاز به اینترنت) |
| پیشنهادهای هوش مصنوعی | فقط اگر `ANTHROPIC_API_KEY` تنظیم شده باشد فعال است |

خروجی: امتیاز کلی از ۱۰۰، امتیاز جداگانه‌ی هر بخش، فهرست «از کجا شروع کنم»،
فهرست کامل ایرادها با فیلتر شدت، و جدول همه‌ی صفحات خزیده‌شده.

### تب «تحقیق کلمات کلیدی»

موضوع را می‌نویسی (مثلاً «قهوه اسپرسو» یا «طراحی سایت») و ابزار:

- عبارت اولیه را با ده‌ها الگو گسترش می‌دهد: سؤالی (`چیست`، `چگونه`، `چرا`)، خریدی
  (`قیمت`، `خرید`، `بهترین`)، آموزشی (`آموزش`، `مقایسه`، `انواع`)، محلی (`در تهران`،
  `نزدیک من`)، زمانی (`۱۴۰۵`، `جدید`) و پویش الفبایی فارسی
- هر عبارت را به پیشنهاد خودکار گوگل، یوتیوب، بینگ و داک‌داک‌گو می‌فرستد
- نتایج را بر اساس نیت جستجو دسته‌بندی و به خوشه‌های موضوعی تقسیم می‌کند
- برای هر خوشه یک صفحه با عنوان و ساختار پیشنهادی می‌دهد
- ترندهای امروز گوگل در کشور انتخابی را هم می‌آورد

**نکته‌ی مهم درباره‌ی اعداد:** ستون «تقاضا» و «فرصت» امتیاز نسبی و تخمینی هستند، نه حجم
جستجوی واقعی. از سه سیگنال ساخته می‌شوند: چند موتور جستجو این عبارت را پیشنهاد داده‌اند،
چند بار در پرس‌وجوهای مختلف تکرار شده، و در فهرست پیشنهادها چندم بوده (موتورها بر اساس
محبوبیت مرتب می‌کنند). برای عدد دقیق حجم جستجو باید از Google Keyword Planner یا سرچ
کنسول استفاده کنی. «فرصت» تقاضا را در برابر سختی احتمالی می‌سنجد و عمداً عبارت‌های
دم‌بلند را بالاتر می‌آورد، چون برای یک سایت شخصی هدف واقع‌بینانه‌تری هستند.

## استفاده از خط فرمان

اگر داشبورد را نمی‌خواهی:

```bash
# بررسی سایت، خروجی Markdown
.venv/bin/python -m seoagent audit example.com --max-pages 50 -o report.md

# با کلمات کلیدی هدف و داده‌ی واقعی سرعت
.venv/bin/python -m seoagent audit example.com --keywords "آموزش سئو,خدمات سئو" --psi

# خروجی JSON برای پردازش بعدی
.venv/bin/python -m seoagent audit example.com --json -o report.json

# تحقیق کلمات کلیدی
.venv/bin/python -m seoagent keywords "قهوه اسپرسو" --lang fa --country IR -o keywords.md

# سریع (بدون پویش الفبایی)
.venv/bin/python -m seoagent keywords "قهوه اسپرسو" --fast

# داشبورد روی پورت دیگر
.venv/bin/python -m seoagent serve --port 8080
```

`--help` روی هر زیردستور فهرست کامل گزینه‌ها را می‌دهد.

## لایه‌ی هوش مصنوعی (اختیاری)

بدون کلید API همه‌چیز کار می‌کند — موتور قوانین کامل است. اگر کلید بدهی، یک لایه‌ی
اضافه با Claude فعال می‌شود که کاری را می‌کند که قانون نمی‌تواند: قضاوت درباره‌ی اینکه
آیا متن صفحه واقعاً به سؤال کاربر جواب می‌دهد، و نوشتن جایگزین.

```bash
.venv/bin/pip install anthropic
export ANTHROPIC_API_KEY="sk-ant-..."
```

بعد از این، تیک «پیشنهادهای هوش مصنوعی» در داشبورد فعال می‌شود (یا `--ai` در خط فرمان).

چه چیزی اضافه می‌کند:

- **در بررسی سایت:** خلاصه‌ی وضعیت، اولویت‌بندی اقدامات با تخمین زحمت و اثر، بازنویسی
  عنوان و متا دیسکریپشن صفحات ضعیف، و فهرست موضوع‌هایی که سایت باید پوشش می‌داد ولی نداده
- **در تحقیق کلمات کلیدی:** زاویه‌های محتوایی که رقبا از قلم می‌اندازند، ساختار زیرتیترها،
  سؤال‌های واقعی کاربران، و موجودیت‌های لازم برای پوشش معنایی کامل

اگر کلید نامعتبر باشد یا شبکه قطع شود، گزارش بدون این بخش تولید می‌شود و دلیلش نمایش
داده می‌شود — چیزی از کار نمی‌افتد.

### Core Web Vitals واقعی (اختیاری)

گزینه‌ی PageSpeed Insights بدون کلید هم کار می‌کند ولی محدودیت نرخ دارد. برای سقف بالاتر:

```bash
export PAGESPEED_API_KEY="..."
```

## چه چیزهایی بررسی می‌شود

بیش از ۴۰ قانون در ۱۰ دسته:

| دسته | نمونه بررسی‌ها |
| --- | --- |
| **ایندکس‌شدن و خزش** | `Disallow: /` سراسری، noindex ناخواسته، تعارض noindex با robots.txt، سایت‌مپ ناقص یا نامعتبر، soft 404، محتوای تکراری، هدررفت بودجه‌ی خزش، آدرس‌های پارامتری |
| **محتوا و کلمات کلیدی** | عنوان (نبود، کوتاه، بلند، تکراری)، متا دیسکریپشن، H1، ترتیب تیترها، محتوای کم‌عمق، انباشت کلمه کلیدی، هم‌نوع‌خواری کلمه کلیدی، Open Graph |
| **فنی** | خطای ۵xx و ۴xx، زنجیره‌ی ریدایرکت، ریدایرکت موقت، HTTPS، محتوای ترکیبی، HSTS، viewport، `lang` و `charset`، ساختار آدرس، فشرده‌سازی |
| **سرعت و Core Web Vitals** | داده‌ی واقعی LCP/INP/CLS، پاسخ کند سرور، منابع مسدودکننده‌ی رندر، حجم HTML، تعداد اسکریپت، هدر کش |
| **داده ساختاریافته** | نبود JSON-LD، خطای نحوی، فیلدهای اجباری ناقص، `@type` گم‌شده، انواعی که گوگل دیگر نتیجه‌ی غنی نمی‌دهد، نبود Organization و BreadcrumbList |
| **لینک‌سازی** | صفحات یتیم، عمق کلیک زیاد، انکرتکست عمومی، لینک بدون متن، پیمایش با `onclick` به‌جای `<a href>`، لینک خروجی خراب |
| **تصاویر** | نبود `alt`، `alt` بیش از حد بلند، نبود `width`/`height` (علت اصلی CLS)، lazy شدن تصویر LCP، فرمت‌های قدیمی، نام فایل بی‌معنا |
| **اعتبار و E-E-A-T** | نبود صفحه‌ی «درباره ما»، «تماس»، «حریم خصوصی»، محتوای بدون نام نویسنده، نبود تاریخ انتشار، نبود ارجاع به منبع، نبود لینک شبکه‌های اجتماعی |
| **چندزبانه** | کد hreflang نامعتبر، نبود خودارجاعی، رابطه‌ی یک‌طرفه، نبود `x-default`، محتوای فارسی بدون `dir="rtl"` |
| **جستجوی هوش مصنوعی** | سیاست خزنده‌های AI در robots.txt، نبود `llms.txt`، زیرتیترهای غیرسؤالی، پاسخ دفن‌شده زیر مقدمه‌ی طولانی، نبود فهرست و جدول، محتوایی که فقط با جاوااسکریپت رندر می‌شود |

هر ایراد شامل این‌هاست: شدت، دسته، توضیح اینکه چرا مهم است، راه‌حل مشخص، فهرست آدرس‌های
متأثر، و لینک به مستندات مرجع گوگل.

### امتیازدهی

هر دسته از ۱۰۰ شروع می‌شود و برای هر ایراد امتیاز کم می‌شود. جریمه بر اساس شدت است و
با تعداد صفحات متأثر به‌صورت زیرخطی (جذری) رشد می‌کند — یعنی یک مشکل سراسری کل دسته را
صفر نمی‌کند. امتیاز کلی میانگین وزن‌دار دسته‌هاست، و **وجود هر ایراد بحرانی سقف امتیاز
کلی را روی ۴۵ می‌بندد**، چون سایتی که از ایندکس خارج شده نباید فقط به‌خاطر خوب بودن
بقیه‌ی موارد چراغ سبز بگیرد. دسته‌هایی که برای سایت موضوعیت ندارند (مثلاً چندزبانه وقتی
hreflang وجود ندارد) اصلاً در میانگین حساب نمی‌شوند.

## خروجی گرفتن

از هر گزارش دو خروجی می‌شود گرفت:

- **Markdown** — برای بایگانی، اشتراک‌گذاری یا باز کردن در نوت‌اپ
- **JSON** — ساختار کامل برای پردازش برنامه‌نویسی یا مقایسه‌ی دو گزارش در طول زمان

گزارش‌ها **در حافظه** نگه داشته می‌شوند و با خاموش شدن سرور پاک می‌شوند. هرچه را
می‌خواهی نگه داری، خروجی بگیر.

### اضافه کردن قانون جدید

یک تابع با دکوریتور `@rule` بنویس که `SiteContext` بگیرد و `Issue` تولید کند:

```python
from ..models import Category, Severity, SiteContext
from .base import make_issue, rule, sample

@rule("my-check")
def check_something(ctx: SiteContext):
    offenders = [p.url for p in ctx.indexable_pages if ...]
    if offenders:
        yield make_issue(
            "my-issue-id",
            "English title",
            "عنوان فارسی",
            "توضیح اینکه چرا این مشکل است و چه اثری روی رتبه دارد.",
            "راه‌حل مشخص و قابل اجرا.",
            Severity.MEDIUM,
            Category.CONTENT,
            offenders,
            sample(offenders),
            "https://developers.google.com/search/docs/...",
        )
```

فایل را در `rules/__init__.py` وارد کن تا ثبت شود. اگر قانونی خطا بدهد، بقیه‌ی بررسی
متوقف نمی‌شود — خطا در یادداشت‌های گزارش ثبت می‌شود.

## محدودیت‌ها

چیزهایی که این ابزار **نمی‌تواند** انجام بدهد، تا انتظار درستی داشته باشی:

- **حجم جستجوی واقعی نمی‌دهد.** هیچ منبع رایگانی این عدد را نمی‌دهد. امتیاز تقاضا تخمین نسبی است.
- **جاوااسکریپت را اجرا نمی‌کند.** فقط HTML اولیه را می‌بیند. اگر سایت کاملاً کلاینت‌ساید
  رندر می‌شود، قانون `client-side-rendered` هشدار می‌دهد ولی محتوای رندرشده تحلیل نمی‌شود.
- **رتبه‌ی فعلی سایت را نمی‌داند.** برای آن به سرچ کنسول نیاز داری.
- **بک‌لینک‌ها را بررسی نمی‌کند.** این کار به دیتابیس‌های تجاری (Ahrefs، Majestic) نیاز دارد.
- **Core Web Vitals آزمایشگاهی محاسبه نمی‌کند** مگر با گزینه‌ی PageSpeed Insights.
- **پیشنهاد خودکار موتورهای جستجو ممکن است محدود شود.** اگر تعداد پرس‌وجو زیاد باشد،
  بعضی منابع موقتاً پاسخ نمی‌دهند؛ این در گزارش به‌عنوان هشدار نمایش داده می‌شود.

## نکته‌ی اخلاقی

ابزار به‌طور پیش‌فرض robots.txt را رعایت می‌کند و بین درخواست‌ها مکث دارد. برای بررسی
سایت‌های خودت ساخته شده. اگر سایت دیگری را می‌خزی، سقف صفحات را منطقی نگه دار و مکث را
کم نکن — بار اضافه روی سرور دیگران بی‌ادبی است.
